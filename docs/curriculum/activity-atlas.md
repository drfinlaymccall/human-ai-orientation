# Activity atlas authoring

The public homepage is a concise Human AI Orientation splash. Its **Explore your course** action opens `/journey`; a verified signed-in session changes that action to **Your course journey**, the private native route `/local/orientation/index.php`. The public journey owns the complete activity-led map: four places for practical work plus optional preparation. Selecting a place reveals what the learner will do, keep and practise, a reflection check and the working activity link. Portfolio practice belongs within the second core activity; the baseline remains the three core activities in `content/course-map.json`. Preparation and the starting-point check remain optional, and public registration remains closed during the pilot gate.

`content/course-map.json` owns labels, public destinations, versions, outcomes, roles and `atlas` descriptions/checks. Edit `content/home.html` for the homepage offer and account wording. `scripts/build-journey.py` expands the journey's `<!-- activity-atlas -->` marker and writes the reusable `content/generated/activity-atlas.html` fragment. Run `npm run build:journey` and retain source/generated pairs. Do not edit generated journey fragments or `public/index.html` directly. The builder also normalises navigation on top-level public course pages, after the preparation/brief builders in `npm run build`, so every header retains Course journey and account access.

The fragment uses `data-atlas-choice`, `data-atlas-detail`, `data-atlas-open` and `data-atlas-progress` attributes with stable manifest slugs. Native publishing can replace public activity hrefs with existing module IDs and fill progress labels from native completion. The fragment itself has no personal data or progress. Native consumers load only the scoped `/assets/activity-atlas.css` and `/assets/activity-atlas.js`; public `site.css` imports that shared stylesheet. Additional optional manifest entries without atlas copy need a native plain-list fallback rather than a fabricated atlas place.

`public/assets/activity-atlas.js` only selects among existing HTML panels. On desktop, details sit beside the illustrated map. At 1000px and below, the selected panel moves immediately after its chosen control; the title and Open this activity action appear before the longer description. The selected control retains focus, Tab moves to its action, and a live announcement confirms the choice. Resizing restores the appropriate placement. All five descriptions, reflection disclosures and destinations remain readable in manifest order without JavaScript; inactive map controls stay hidden. No selections, answers or self-ratings are saved and no completion is marked by this enhancement.

`public/assets/account-state.js` makes a same-origin GET to `/local/orientation/state.php` with credentials, `cache: no-store` and a no-store request header. The response contract is `{ "state": "signed-in" | "signed-out", "journey_url": "/local/orientation/index.php" }`. Only that fixed native path is accepted. No identity, personal progress, local-storage inference or caller-selected account is used. Headers show **Your course journey** when signed in and **Sign in** when signed out. Pending, failed, malformed or JavaScript-free checks retain **Check sign-in / Your course journey** and a working public route. Page restoration/tab return revalidates; leaving clears the resolved presentation. The native endpoint must provide private/no-store response headers and remain excluded from shared caches. Account links enter the native journey so login preserves the intended destination.

The optional **Find my starting point** link enters `/local/orientation/startingpoint.php`. Its nearby copy explains sign-in, saved ratings and limited account availability. The native instrument and privacy wording are a separate U8 delivery/verification gate; this public link is not evidence that the check has been released.

Preserve exactly one `<!-- orientation-return-guidance -->` / `<!-- /orientation-return-guidance -->` pair in the generated journey. The native publisher replaces only this region with account-specific saving guidance. Public portfolio fields remain temporary browser drafts with private downloads/JSON restore; they must not be described as account-backed storage.

Allow entry at any destination with an existing task/context or a clearly labelled fictional example. Learner labels use ordinary language without capability codes or taxonomy jargon. The preserved [design prototype](../prototypes/orientation-activity-atlas.html) retains the author relationship view; its host-widget controls and author-only toggle are not deployed.

Run `npm run test:entry` after rebuilding. The focused suite uses its dedicated local preview port 18801, not a native Moodle fixture. Synthetic browser checks cover splash versus journey, all five destinations, nearby desktop/320/390px details, selected-action keyboard access, no-JavaScript reading, the full public sequence and direct final-activity entry. Mocked same-origin responses cover signed-in, signed-out, failed, slow, invalid URL and restored-page account presentation across public course headers. Screenshot review checks actual desktop/mobile layout. These are navigation and presentation checks, not evidence of human comprehension, learning, physical-device use or the native endpoint's privacy/cache behaviour. Root release documentation carries the combined U1/U3/U8 evidence and current CONTROL status.
