## The process

1. Finlay described the audience, useful-task approach, bring-your-own-AI model and desired public demonstration of complete digital-learning delivery.
2. A discovery interview tested audience assumptions, learner outputs, support expectations, hosting, timeline and priorities.
3. The design brief connected needs, intended capabilities, activities, assessment evidence and operational requirements. Research informed choices; it was not treated as proof of course effectiveness.
4. CONTROL.md separated Now, Next and Later, recorded the three-activity launch scope and kept a place for ideas without silently making them commitments.
5. A complete context lesson was built in a private Moodle trial. Account creation, lesson completion, reflection, return and captured email were exercised before public hosting.
6. Finlay inspected the course and supplied iterative feedback. Shared public/Moodle content, editable examples, computer preparation, prompting tips and continuity between steps followed that feedback.
7. The next review made the portable context portfolio explicit as the course's organising outcome. Export and restore moved forward; a human pilot remains the source for subsequent expansion decisions.
8. Git began with commit `2e2752a`, preserving the working prototype. Later changes use commits, a review branch, pull requests, issue links and dated release evidence. Earlier conversation history is recorded here without fabricated historical commits.

## Roles and limits

Finlay sets purpose, priorities, pedagogy and publication choices and reviews the learner experience. Codex assists with research, drafting, implementation and synthetic verification. Other agent work is identified in release notes. Synthetic tests establish specific software behaviour; they do not establish learning gain or stand in for a human pilot. Finlay's own walkthrough is founder feedback, not a three-to-five-person study. The broader human–agent curriculum-design programme is separate.

## Ongoing record

For each meaningful iteration record: user need or observation; decision and alternatives; files/activities affected; research basis; checks and limits; commit/PR; next evidence needed. Do not publish private learner portfolios or support conversations. Public design discussion can be summarised with attributable excerpts; learner examples need consent or must be explicitly fictional.
